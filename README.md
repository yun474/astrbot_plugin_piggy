## ✨ 能玩什么

- 每天抽一只小猪；当天重复使用会看到同一只，收藏跨群共享。
- 在图鉴里查看解锁进度，在猪圈里翻看已收藏的小猪。
- 查看种类榜和数量榜，也可以设置自己的展示称呼。
- 和群友交换小猪，或者发起斗猪：回合制自动对战，赢家把输家出战的那只猪收进自己的猪圈。
- 逛逛每日小猪商店：每天 5 只，每只限量 1 个，用自己的小猪先到先换。
- 四人组队刷猪副本：三个副本、九个各有专属机制的 boss，还有一大堆随机事件，打赢就能把 boss 猪带回家。

## 🚀 安装与使用

在 AstrBot 插件管理中使用仓库地址 `https://github.com/kurtloong/astrbot_plugin_piggy` 安装。需要 AstrBot 3.5.3 或更新版本。若已启用旧版“今日小猪”插件，请先停用，避免指令冲突。

本仓库基于 [yun474 的原版](https://github.com/yun474/astrbot_plugin_piggy)，新增了斗猪与交换。已经安装原版的用户需要先卸载，再用上面的地址重新安装。卸载时请保留插件数据，大家的收藏不会丢失。重新安装后，插件管理里的“更新”就会从本仓库拉取。

在 QQ 群里 @机器人发送：

| 指令 | 用途 |
| --- | --- |
| `今日小猪` / `抽小猪` | 抽取当天的小猪，可能触发猪群聚集和小猪连抽；有再抽机会时当天再发一次即可再抽 |
| `小猪图鉴 [页码]` | 查看全部小猪和解锁进度 |
| `我的猪圈 [页码]` | 查看自己的收藏 |
| `小猪排行` | 查看种类榜和数量榜 |
| `小猪称呼 名字` | 设置展示称呼，限 1–24 字 |
| `小猪玩法` / `小猪帮助` | 查看等级、斗猪和交换的玩法说明 |
| `小猪属性 小猪` | 查看自己这只小猪的等级、属性和 5 个技能 |
| `斗猪 @对方 我的小猪` | 向群友发起斗猪 |
| `接受斗猪 我的小猪` / `拒绝斗猪` | 选好出战小猪应战，或拒绝 |
| `小猪交换 @对方 我的小猪 对方的小猪` | 向群友发起一换一交换 |
| `接受交换` / `拒绝交换` | 处理收到的交换请求 |
| `我的请求` / `取消请求` | 查看本群待处理请求 / 撤回自己发出的请求 |
| `斗猪排行` | 本群玩家斗猪胜率排行，至少 3 场上榜 |
| `斗猪记录 [页码]` | 以图片卡片查看自己的斗猪历史战绩 |
| `斗猪回放 编号` | 重看自己参与的某场斗猪的对决海报 |
| `小猪商店` | 以图片卡片查看本群今日商店：每天 0 点上架 5 只小猪，每只限量 1 个 |
| `小猪挑战` | 查看本群今天的野生小猪（每天一只，1–20 级随机） |
| `挑战小猪 我的小猪` | 挑战野猪：输了失去出战的猪，赢了收服它并让全群各得 1 次再抽 |
| `商店交换 编号 我的小猪` | 用自己的 1 只小猪换走商店里的那只 |
| `猪副本` | 查看 3 个副本、9 个 boss 的机制，以及本群的组队情况 |
| `开启副本 编号 我的小猪` | 发起副本组队（1 冰封猪圈 / 2 机械猪厂 / 3 猪神殿） |
| `加入副本 我的小猪` | 加入本群正在组队的队伍，满 4 人自动开打 |
| `退出副本` | 组队期间退出；队长退出则整队取消 |
| `继续副本` / `撤退副本` | 队长在打完一关后决定继续下一关还是带着奖励撤退 |
| `小猪重载` | 管理员应用猪库修改 |
| `小猪备份` | 管理员创建本地备份 |
| `小猪诊断` | 管理员检查图床上传与 QQ 图片发送 |

每天按东八区自然日计算抽取次数。同一 QQ 官方机器人应用下，收藏和每日抽取结果跨群共享。

**猪群聚集与小猪连抽**：每抽到一只猪（包括连抽出来的），先按「猪群聚集概率」判定是否再得到 1 只相同的猪，再按「小猪连抽概率」判定是否继续抽一只新猪，新猪同样会再判定，数量没有上限。期望数量为（1 + 聚集概率）÷（1 − 连抽概率），默认两者都是 50%，平均每次 3 只。抽到的所有小猪都会画在同一张卡片上，并标出「聚集」「连抽」和「NEW」。当天再发「今日小猪」会显示今天最近一次的结果。

**野猪挑战与再抽**：每个群每天出现一只野生小猪，等级在 1 到「野生小猪最高等级」（默认 20）之间随机。发送 `挑战小猪 你的小猪` 用自己的猪挑战，次数不限，也不占每日斗猪次数。输了会失去出战的那 1 只（和斗猪落败一样）；赢了收服这只野猪，同时本群所有玩家当天各获得 1 次再抽机会。野猪被收服后当天不再刷新，第二天 0 点出现新的。再抽机会只在当天、当群有效：今天已经抽过的玩家再发 `今日小猪`，会自动消耗 1 次机会再抽一组，同样可能触发聚集和连抽。

每日抽猪默认开启重复保护：重复概率不超过 20%，连续两次抽到已拥有的小猪后，下次必出未收集的小猪（如有）。实际重复概率为「已拥有的启用种类数 / 启用总种类数」与配置上限的较小值，新玩家不会被提高重复概率。先决定抽新猪还是重复猪，再在对应池内等概率抽取。

保底按实际抽取次数计算，已有历史也计入；漏签不清零，同一天重复查看不累计。停用的小猪不参与抽池及概率分母。全部集齐后正常抽取重复猪，添加新猪后自动恢复保护。配置调整不会重抽当天结果。图床消息与直接发送的卡片都会在仍有新猪时显示重复保护进度。

## ⚔️ 斗猪与交换

每只小猪都有按简介设计的流派、属性（生命、攻击、防御、速度、暴击、闪避）和 5 个专属技能。**等级等于拥有的同种猪数量**，比如 5 只猪人就是 Lv5。每升一级，生命、攻击、防御、速度提高 8%；1–5 级依次解锁 5 个技能。等级上限默认 20，可在配置中调整。

- **发起**：`斗猪` 和 `小猪交换` 需要 @ 对方。如果 @ 识别不到（例如对方设置了群名片时，QQ 可能不会把这个 @ 推送给机器人），可以改用对方的玩家编号，例如 `斗猪 #12 猪人`。编号显示在「我的猪圈」和「小猪图鉴」卡片的名字后面，也会出现在 `斗猪排行` 里。还可以写对方在本插件里的称呼或 QQ 昵称（不是群名片），重名时请改用编号。
- **斗猪**：对方发送 `接受斗猪 小猪名` 选择出战小猪后立即开打。双方按速度轮流出手，自动释放已解锁的技能，最多 20 回合，结束后发送一张对决海报：双方小猪、等级、剩余血量和胜负，以及不省略的完整战斗过程和结算；回合用完时按剩余生命比例判定胜负。第 8 回合后伤害会逐回合提高，避免双方无限拖延。
- **结算**：败者只失去出战的那 **1 只** 小猪，归胜者所有。等级按数量实时计算，所以败者这种猪会降 1 级，低于解锁等级的技能随之重新锁上；如果是最后一只，这种猪会从猪圈中消失。胜者这种猪的数量加 1，等级也随之提升。
- **交换**：一换一，双方各交出 1 只。成交时会再次检查双方是否仍拥有这只猪，等级同样随数量变化。
- **战绩**：`斗猪排行` 按胜率排列本群玩家，至少 3 场上榜；`斗猪记录` 查看自己的历史对战，`斗猪回放 编号` 重看某场的完整战报。
- **限制**：每人在每个群同一时间最多发出 1 个、收到 1 个同类请求；请求默认 10 分钟后过期。发起和应战都计入每日斗猪次数，默认每天 5 场。不能对自己发起请求。

**每日小猪商店**：每个群各有一个商店，每天东八区 0 点刷新。当天第一次有人查看时，从启用的小猪中随机上架 5 只不同的小猪。发送 `商店交换 编号 你的小猪`，用自己的 1 只小猪换走对应编号的那只；交出的小猪由商店收走，等级随数量下降，换到的小猪计入你的猪圈。每件只有 1 个库存，被换走后本群其他人就换不到了，同时交换时也只有一人成功。不能用同一种小猪换同一种。

**猪副本**：内置三个副本，每个副本 3 个 boss，每个副本每人每天 1 次。

- **组队**：发送 `开启副本 编号 你的小猪` 发起，你就是队长；群友发送 `加入副本 他的小猪` 加入。必须正好 4 人才出发，第 4 人加入时自动开打第一关，这条加入指令的回复就是第一关的战报。组队 10 分钟内没满员会自动取消，不扣次数。开打后不能中途加入，有人倒下也不补人。同一个群同一时间只有一支队伍，一个玩家也只能在一支队伍里。QQ 官方机器人不能主动发群消息，所以超时取消要等下一次有人发副本相关指令时才会提示。
- **团战**：4 只队员猪同时上场，与 boss 按速度轮流出手，最多 25 回合，回合用完 boss 没倒下就算失败。boss 与队伍的平均等级同级，后面的关卡生命和攻击更高。每关开打前会抽 1–2 个进场事件，战斗中还可能触发场地事件。
- **继续还是撤退**：每打赢一关，队长 10 分钟内发送 `继续副本` 或 `撤退副本`，不决定就自动撤退。存活的猪带着剩余血量进入下一关，出发前先回复 30% 生命，路上还可能遇到关间事件。
- **奖励与惩罚**：和小猪挑战一致。每打赢一关，每位队员各得 1 只 boss 猪，本群所有玩家当天各得 1 次再抽；战斗中倒下的猪，主人失去 1 只，本副本内也不能再上场，全员倒下就算团灭。撤退时已经得到的奖励都保留。等待期间如果出战的猪被斗猪输掉或换走了，这名队员下一关只能缺席。
- **boss 机制**：9 个 boss 各有 3 个专属机制，`猪副本` 指令会全部列出。如果管理员停用了某个 boss 猪，会由一只随机小猪“附身”顶上，机制不变。

战斗数据保存在插件数据目录的 `catalog/battle.json`，首次启动时从插件自带的数据复制过来，之后不会被插件更新覆盖。管理员修改后发送 `小猪重载` 生效；校验失败时会保留上一份有效数据。没有配置战斗数据的新猪会使用均衡的默认属性和技能。

斗猪和交换消息默认以纯文字发送。如果机器人有 Markdown 消息权限，可以开启「斗猪/交换使用 Markdown 与按钮」：开启后消息会 @ 对方，并附带接受和拒绝按钮；按钮谁都能点，但只有被邀请的本人发出才会生效。

## 🎛️ 图片发送方式与 R2 配置

插件可以直接向 QQ 发送图片，也可以通过图床发送带快捷按钮的消息。在插件配置的「消息展示」中，分别设置「今日小猪」「小猪图鉴」「我的猪圈」「小猪排行」是否使用图床。默认只有「今日小猪」开启图床；如果没有图床，请先关闭这个开关，其余功能默认可直接使用。

开启图床时，需要在插件配置中填写 R2 / S3 或 HTTP 图床信息；图片公网地址必须能由 QQ 直接访问。使用 R2 时，`endpoint` 填上传接口，`public_base_url` 填已绑定存储桶的公网域名，两者不要填反。若把图鉴、猪圈或排行也设为图床模式，建议给 R2 的 `piggy/temp/` 设置 7 天后删除的生命周期规则，避免临时卡片长期占用空间。

快捷按钮会按「快捷指令唤醒词」生成命令。默认留空即可在 @机器人后直接使用；如果 AstrBot 设置了 `/`、`!` 等唤醒词，请在这里填写相同内容。

## ⚙️ 配置项说明

以下是插件配置页中的选项及默认值。不使用图床时，关闭各个「使用图床」开关即可，图床相关选项无需填写。

| 消息与日常设置 | 默认值 | 说明 |
| --- | --- | --- |
| `duplicate_rate_cap`（重复概率上限） | `20` | 0–100，单位 %；0=有新猪必出新猪，100=自然重复概率。集齐后不受上限限制 |
| `duplicate_pity`（连续重复保底次数） | `2` | 0–30；连续重复达到此次数，下次必出新猪（如有）；0=关闭保底 |
| `draw_gather_chance`（猪群聚集概率） | `50` | 0–90，单位 %；每抽到一只猪，按此概率再得 1 只相同的猪 |
| `draw_chain_chance`（小猪连抽概率） | `50` | 0–90，单位 %；每抽到一只猪，按此概率继续抽一只新猪 |
| `wild_level_max`（野生小猪最高等级） | `20` | 1–100；每日野猪的等级在 1 到此值之间随机 |
| 今日小猪使用图床 | 开启 | 通过图床发送，附带快捷按钮；关闭后直接发送图片 |
| 小猪图鉴 / 我的猪圈 / 小猪排行 / 小猪商店 / 斗猪海报与记录 / 野猪卡片与挑战海报 / 猪副本战报使用图床 | 关闭 | 可分别开启；开启后通过图床发送并附带快捷按钮 |
| `command_prefix`（快捷指令唤醒词） | 留空 | 使用自定义唤醒词时，填与 AstrBot 相同的内容 |
| `backup_keep`（本地备份保留份数） | `7` | 自动和手动备份最多保留的份数 |
| `battle_level_cap`（小猪等级上限） | `20` | 5–100；拥有数量超过上限时按上限计算等级 |
| `duel_daily_limit`（每日斗猪场数上限） | `5` | 1–100；发起和应战都计入，按东八区自然日计算 |
| `request_ttl_minutes`（请求有效期） | `10` | 1–60 分钟；超时未处理的斗猪或交换请求自动作废 |
| `battle_markdown`（斗猪/交换使用 Markdown 与按钮） | 关闭 | 开启后 @ 对方并附带接受/拒绝按钮，需要 Markdown 权限 |

**图床配置：** 打开「展开图床配置」，在 `image_host.provider` 中选择图床，页面只显示对应参数。收起仅影响显示，不会停用图床。各类型独立保存，切换回来无需重填；各消息功能共用当前选中的图床。

可选 Cloudflare R2（默认）、AWS S3、阿里云 OSS、腾讯云 COS、七牛云 Kodo、MinIO、Backblaze B2、DigitalOcean Spaces、其他 S3 兼容存储、兰空 Lsky Pro V2 和自定义 HTTP。对象存储通过 S3 兼容接口上传，请使用服务商提供的 S3 端点与凭据。

旧版配置首次加载时自动保存到「其他 S3 兼容存储」和「自定义 HTTP」分组，保留原选中的上传方式；已有新分组配置优先。旧 R2 配置会保留在「其他 S3 兼容存储」中，仍可照常使用。

**对象存储：** 参数位于 `image_host` 下的对应分组（`r2`、`aws`、`oss`、`cos`、`qiniu`、`minio`、`b2`、`spaces`、`s3`）：

| 配置项 | 默认值 | 填写内容 |
| --- | --- | --- |
| `endpoint` | 留空 | 上传接口；R2 格式为 `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` |
| `bucket` | 留空 | 存储桶名称 |
| `access_key` / `secret_key` | 留空 | 存储桶的上传凭据 |
| `public_base_url` | 留空 | 可公开访问图片的域名，如 `https://img.example.com` |
| `region` | 按类型预设 | R2 为 `auto`；OSS、MinIO、通用 S3 为 `us-east-1`；其他类型填写实际区域 |
| `addressing_style` | `auto` | 自动按类型选择；OSS 固定为 `virtual`，其他类型可手动指定 |

阿里云 OSS 使用 S3 V2 签名与虚拟主机寻址，遵循其 [S3 兼容接口要求](https://www.alibabacloud.com/help/en/oss/developer-reference/compatibility-with-amazon-s3)。其他对象存储使用 S3 V4 签名。

**兰空 Lsky Pro V2：** 在 `image_host.lsky` 填写完整上传地址（例如 `https://你的图床/api/v1/upload`）和 Authorization 值（例如 `Bearer 你的Token`）。插件自动设置文件字段、响应路径与成功状态检查。

**自定义 HTTP：** 在 `image_host.http` 中按上传 API 填写：

| 配置项 | 默认值 | 填写内容 |
| --- | --- | --- |
| `upload_url` | 留空 | 完整的上传地址 |
| `upload_mode` | `multipart` | 文件上传用 `multipart`；要求 Base64 JSON 时选 `json_base64` |
| `upload_headers` / `upload_fields` | `{}` / `{}` | 图床要求的请求头和附加字段，均填写 JSON 对象 |
| `file_field` | `file` | 图片字段名 |
| `response_url_path` | `data.links.url` | 上传结果中图片直链的位置，如 `image.url` |
| `success_path` / `success_value` | 留空 / `true` | 图床返回成功标记时填写；无成功标记可留空 `success_path` |

**重试与缓存：** 打开「展开重试与缓存设置」后显示，一般保持默认即可。上传重试和请求超时也用于 QQ 直传，因此独立于图床选择保存。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `upload_retry_count` / `image_retry_count` | `2` / `3` | 上传失败、QQ 图片发送失败后的额外重试次数；`0` 表示不重试 |
| `retry_base_delay` / `request_timeout` | `1` 秒 / `20` 秒 | 重试等待的基础间隔、单次网络请求的超时时间 |
| `cache_ttl_hours` | `168` 小时 | 固定猪图的图床链接缓存时间；应短于图床链接有效期 |
| `temp_cache_hours` | `12` 小时 | 临时卡片链接复用时间；不会自动删除图床图片 |

<a id="catalog"></a>

## 🧩 猪库维护

首次启动会在 `data/plugin_data/astrbot_plugin_piggy/catalog/` 生成猪库。管理员可编辑 `pigs.json` 和 `images/` 中的图片，再发送 `小猪重载` 应用修改。新增小猪时添加新条目和图片；下架时将对应条目的 `enabled` 设为 `false`。请勿把旧 `id` 分配给另一种猪，以免合并原有收藏。历史收藏不会因下架而删除。

插件随包附带约 978 只小猪，图鉴会分多页显示。插件升级时，启动会自动把新随包的小猪（以及它们的战斗数据）补进已有猪库：管理员改过的条目不会被覆盖，删除过的小猪也不会被加回来（记录在 `catalog/.bundled_ids` 中）。战斗数据重新平衡后，管理员没改过的条目会自动换成新数值，改过的保持不变。想停用某只随包小猪，推荐把 `enabled` 设为 `false`。

<a id="backup"></a>

## 💾 数据备份

插件会在启动时及之后每 24 小时自动备份；也可以发送 `小猪备份`。备份文件位于插件数据目录的 `backups/`，包含收藏数据、猪库、战斗数据和历史图片。恢复时先停用插件，保留原数据目录作回退，再将可信备份解压到新的空插件数据目录，最后启用插件。图床凭据保存在 AstrBot 配置中，不包含在备份里。
